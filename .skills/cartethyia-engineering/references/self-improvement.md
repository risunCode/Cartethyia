# Skill self-improvement

Update a skill only after a repeated failure, a rejected change, or a newly found
drift class.

1. **Find the closest owner first.** Extend it. Add a new skill folder only when
   the topic has its own trigger and no existing folder owns it — one folder, one
   skill. A competing file that restates another is worse than no file.
2. Keep guidance procedural: state the trigger, the required check, the failure
   mode, and the evidence.
3. Verify every cited path, symbol, command, and export before writing it. A
   comment or skill that names a symbol must name one that exists.
4. Remove guidance that no longer matches the repository.
5. Do not repeat the gate list or shared rules in a second file; point at
   `verification.md` or `guards.md`.

The skill teaches a reusable decision or verification step, not a one-off
implementation note.
