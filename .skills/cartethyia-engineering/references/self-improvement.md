
# K10 Skill self-improvement

Use after a cleanup review, rejected change, or newly discovered drift class.

## Required check

1. Confirm the lesson is procedural and reusable, not a one-off implementation note.
2. Search existing `.skills/` files before adding or changing a skill; extend the closest owner instead of duplicating it.
3. State the trigger, required check, failure mode, and evidence expected from the skill.
4. Register the skill in `AGENTS.md` when it is a required guard, and keep examples tied to current repository authorities.

## Evidence

Report the repeated failure or drift class, the skill that owns it, and why no competing skill now exists.
